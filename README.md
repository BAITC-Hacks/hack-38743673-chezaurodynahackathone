# SmartMatch

SmartMatch помогает заказчику выбрать до трёх event-подрядчиков из уже сформированного каталога. Сервис сначала исключает профили с неполными критическими данными и кандидатов, которые не проходят условия заказа. Только после этого он детерминированно ранжирует оставшихся и объясняет каждую рекомендацию фактами из конкретного профиля.

## Что реализовано

- Вход: город, дата, тип мероприятия, категория, бюджет; опционально язык, длительность и свободный текст с приоритетами.
- Жёсткая проверка критических данных: id, имя, категория, город, положительная цена, форматы, языки, календарь и описание. Неполные строки помещаются в карантин и не участвуют в подборе.
- Последовательные фильтры по городу, категории, занятости, бюджету, формату, языку и длительности.
- До трёх карточек с уникальным объяснением в 1–2 предложениях. Объяснение называет дату, цену, запас бюджета и подтверждающий фрагмент описания.
- Три явных исхода: подбор выполнен; в городе нет категории; кандидаты есть, но условия не прошёл никто.
- Объяснение частичной выдачи, если подходящих профилей меньше трёх.
- Отдельные метки исходных и синтетических профилей, а также восстановленных города и цены.
- Видимый путь кандидатов через фильтры и причины исключения.
- Одинаковый порядок для одинакового запроса.
- Автономная веб-демонстрация без внешних API и сторонних Python-пакетов.

## Основной сценарий

1. Пользователь задаёт параметры мероприятия.
2. Quality gate удаляет записи без критических данных.
3. Алгоритм находит профили нужной категории и города.
4. Занятые, слишком дорогие и не соответствующие формату, языку или длительности кандидаты исключаются.
5. Оставшиеся профили получают балл по фиксированной формуле.
6. Сервис возвращает до трёх карточек и показывает, какие факты определили их порядок.

## Ранжирование

Скоринг применяется только после жёстких фильтров. Итоговый балл состоит из пяти сигналов:

| Сигнал | Вес | Назначение |
|---|---:|---|
| Смысл описания | 34% | TF-IDF-подобное совпадение запроса с текстом профиля |
| Соответствие бюджету | 30% | Предпочтение разумному использованию бюджета с резервом |
| Язык | 12% | Совпадение с указанным языком |
| Длительность | 10% | Запас по максимальному времени на площадке |
| Качество исходных данных | 14% | Небольшой штраф за синтетический профиль или восстановленные город и цену |

При равенстве баллов сначала выбирается меньшая цена, затем лексикографически меньший `id`. Поэтому случайность отсутствует.

## Объяснения

Объяснение строится из данных уже прошедшего профильного фильтра. Первая фраза подтверждает свободную дату и бюджет. Вторая использует наиболее релевантное предложение из описания и, если заданы, язык и длительность. Шаблонные оценки вроде «отличный выбор» не используются.

## Технологии и архитектура

- Python 3.11+
- стандартная библиотека Python: `csv`, `dataclasses`, `http.server`, `unittest`
- HTML, CSS и JavaScript без внешних CDN
- локальный полнотекстовый индекс с нормализацией русских слов и TF-IDF-подобным cosine score

```text
CSV → проверка критических полей → нормализованный каталог
                                      ↓
Форма → жёсткие фильтры → текстовый и числовой скоринг → объяснения → карточки
                         ↘ аудит причин исключения ↗
```

Ключевые модули:

- `smartmatch/repository.py` — загрузка CSV, типизация и карантин неполных строк.
- `smartmatch/engine.py` — фильтры, скоринг, исходы и объяснения.
- `smartmatch/text.py` — детерминированный текстовый индекс и выбор доказательного фрагмента.
- `smartmatch/web.py` — локальный HTTP API и раздача интерфейса.
- `smartmatch/static/` — демонстрационный интерфейс.

## Установка и запуск

Нужен Python 3.11 или новее. Дополнительные библиотеки не требуются.

```bash
python run.py
```

Откройте `http://127.0.0.1:8000`.

Другой порт:

```bash
python run.py --port 8080
```

Docker:

```bash
docker build -t smartmatch .
docker run --rm -p 8000:8000 smartmatch
```

## Как проверить решение

В интерфейсе доступны четыре готовых сценария:

1. Плотная категория: ведущий в Алматы на осеннюю дату.
2. Редкая категория: флорист на свадьбу.
3. Кандидаты есть, но не проходят ограничения.
4. В выбранном городе нет нужной категории.

Автоматическая проверка:

```bash
python -m unittest discover -s tests -v
python scripts/evaluate.py
```

Тесты проверяют детерминизм, отсутствие занятых или слишком дорогих профилей в выдаче, три исхода, изменение результата по дате, время ответа и карантин строки без города.

## API

`POST /api/recommend`

```json
{
  "city": "Алматы",
  "event_date": "2026-10-15",
  "event_format": "корпоратив",
  "category": "Ведущий",
  "budget_kzt": 1500000,
  "duration_hours": 6,
  "language": "русский",
  "preferences": "интеллигентный ведущий для бизнес-аудитории"
}
```

`GET /api/meta` возвращает доступные значения формы и демо-сценарии. `GET /api/health` предназначен для проверки доступности сервиса.

## Данные и внешние сервисы

В `data/contractors.csv` находится предоставленный организаторами анонимизированный датасет из 66 профилей. В нём 53 исходных и 13 синтетических профилей. Календарь покрывает период с 23 сентября по 31 декабря 2026 года.

Приложение не отправляет данные во внешние сервисы. Для MVP это обеспечивает воспроизводимость, малую задержку и стабильный порядок. Архитектура допускает замену локального текстового индекса на embeddings, если появятся большая выборка и проверяемый набор релевантности.

## Ограничения

- Цена трактуется как нижняя граница стоимости, а бюджет — как максимальная сумма.
- Календарь содержит только занятые даты; свободное время внутри дня не моделируется.
- Локальный текстовый индекс понимает совпадения слов и их простых форм, но не заменяет полноценную семантическую модель.
- Нет бронирования, заявок и уведомлений подрядчикам: сервис выдаёт только рекомендацию.
- Нет развёрнутой публичной версии. Приложение запускается локально или через Docker.
