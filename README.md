# SmartMatch — подбор подрядчиков по описанию

Рабочий сайт HackAlem AI: HTML, CSS и JavaScript с сервером на Python. Заказчик описывает мероприятие обычным текстом, проверяет распознанные параметры и получает до трёх подрядчиков из предоставленных 66 профилей. У каждой карточки есть объяснение на основе конкретного профиля.

Репозиторий команды: https://github.com/BAITC-Hacks/hack-38743673-chezaurodynahackathone

## Быстрый запуск

Требуется Python 3.11+. Сторонние Python-пакеты устанавливать не нужно.

```bash
python run.py
```

Откройте http://127.0.0.1:8000. В Windows также можно открыть `Запустить SmartMatch.cmd`.

HTML страницы находится в `smartmatch/static/index.html`. Открывайте сайт через сервер: двойной щелчок по HTML не запускает подбор и не подключает ИИ.

## Подключение OpenAI

1. Скопируйте `.env.example` в `.env` в корне проекта, рядом с `run.py`.
2. Впишите свой серверный ключ после `OPENAI_API_KEY=`.
3. Перезапустите сервер. Интерфейс покажет, что OpenAI настроен, и включит переключатель ИИ.

```dotenv
SMARTMATCH_AI_PROVIDER=openai
SMARTMATCH_AI_MODEL=gpt-4.1-mini
OPENAI_API_KEY=your_server_key_here
SMARTMATCH_AI_TIMEOUT=8
```

Для контейнера используйте переменные окружения или `--env-file .env`:

```bash
docker build -t smartmatch .
docker run --rm --env-file .env -p 8000:8000 smartmatch
```

`.env` исключён из Git и Docker-образа. Ключ не отдаётся браузеру и не записывается в сообщения об ошибках. Переменные окружения имеют приоритет над `.env`. Сам файл с ключом не следует публиковать.

Подключение использует [OpenAI Responses API](https://developers.openai.com/api/docs/guides/text) и [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Успешный реальный вызов зависит от действующего ключа, доступа к модели, сети и лимитов аккаунта. Без ключа сайт работает в явно обозначенном локальном режиме; он не выдаёт поиск по словам за работу нейросети.

## Как пользоваться

- Напишите, кого ищете, где и когда будет мероприятие, какой бюджет и формат.
- Нажмите «Заполнить по описанию». Проверьте поля: неуказанные обязательные условия нужно заполнить. Ручные исправления сохраняются и имеют приоритет перед описанием.
- Нажмите «Найти подрядчиков». Если описание ещё не разобрано, первое нажатие заполнит параметры для проверки, второе выполнит подбор.
- В карточке прочитайте аргументы выбора, формат, язык, длительность, происхождение данных и календарь занятости.
- В блоке «Как прошёл отбор» видны количество профилей после каждого фильтра и причины исключения.

В интерфейсе есть примеры корпоратива и свадьбы. «Посмотреть на примере» выполняет локальный подбор и не расходует API. Кнопка «Сбросить» очищает параметры для нового заказа. Если условия изменены после подбора, старый список помечается как требующий обновления.

## Что делает ИИ

Первый вызов извлекает город, дату, категорию, формат, бюджет, язык и длительность из описания. Отсутствующие условия модель должна оставить пустыми. Полученные значения дополнительно проверяются на сервере, затем пользователь видит их в редактируемой форме.

Перед вторым вызовом сервер применяет жёсткие фильтры: город, категория, занятость, бюджет, формат, язык и длительность. ИИ получает только прошедшие профили и оценивает соответствие их описаний запросу. Ответ принимается, только если все идентификаторы принадлежат этому списку, оценки конечны и лежат в диапазоне 0–100, а каждая цитата буквально присутствует в исходном описании. Модель не может добавить кандидата, изменить цену или отменить фильтр. Объяснения строятся из подтверждённых фактов и проверенной цитаты.

В OpenAI отправляются описание заказа, его параметры и описания прошедших фильтры подрядчиков с анонимными идентификаторами. Запросы используют `store: false`. Без ИИ внешних запросов нет. При ошибке API, тайм-ауте или недостоверном ответе сайт явно показывает переход на локальный поиск.

## Ранжирование и воспроизводимость

| Сигнал | Вес |
|---|---:|
| Соответствие описания — оценка ИИ или локальный текстовый индекс | 34% |
| Соответствие бюджету | 30% |
| Язык | 12% |
| Длительность | 10% |
| Качество исходных данных | 14% |

При равном балле сначала выбирается меньшая цена, затем идентификатор. Балл — оценка ранжирования, а не вероятность успешного мероприятия.

Локальный режим детерминирован. Успешные ответы ИИ кэшируются в памяти сервера для одинаковых запросов, максимум 128 записей; параллельные одинаковые запросы синхронизированы. После перезапуска, вытеснения из кэша или восстановления API результат ИИ может измениться. Для строгой воспроизводимости на демонстрации отключите ИИ. Жёсткие фильтры одинаковы в обоих режимах.

## Данные и ограничения

- CSV: `data/contractors.csv`, 66 профилей: 53 исходных и 13 синтетических.
- У 8 профилей город восстановлен, у 18 восстановлена цена; эти признаки видны в карточках.
- Календарь: **23 сентября — 31 декабря 2026 года**. Другие даты не принимаются.
- У 9 профилей длительность не применяется к категории; отсутствие `max_hours` не считается ограничением.
- Цена в выборке указана «от», бюджет трактуется как максимум. Окончательную стоимость подтверждает подрядчик.
- Занятость известна только по предоставленному календарю; контактов и бронирования нет.
- Отдельно показаны ситуации «категории нет в городе» и «категория есть, но все кандидаты исключены». Если осталось меньше трёх, выводятся все подходящие с объяснением.
- Локальный текстовый поиск не понимает смысл и отрицания так же, как языковая модель.

Сервер предназначен для локальной демонстрации и хакатона. Для открытого промышленного размещения нужны HTTPS, авторизация/лимиты пользователей и промышленный HTTP-сервер перед приложением; встроенное ограничение параллельных запросов к ИИ не заменяет квоты пользователей.

## API и файлы

- `GET /api/meta` — списки значений, календарь, статистика, статус настройки ИИ без ключа.
- `POST /api/parse-brief` — `{ "description": "...", "use_ai": true }`; ответ содержит `query`, `missing_fields`, `warnings`, `mode`, `message`.
- `POST /api/recommend` — параметры ниже; ответ содержит до трёх карточек, аудит фильтров и фактический режим `ai.used`.
- `GET /api/health` — доступность сервера.

```json
{
  "city": "Алматы",
  "event_date": "2026-10-06",
  "event_format": "корпоратив",
  "category": "Ведущий",
  "budget_kzt": 1000000,
  "language": "русский",
  "duration_hours": 5,
  "preferences": "Интеллигентная подача для бизнес-аудитории",
  "use_ai": true
}
```

Основные модули: `brief.py` — разбор; `ai.py` — серверное подключение и валидация; `hard_filter.py` — ограничения; `engine.py` — скоринг и фактические объяснения; `repository.py` — проверка CSV; `web.py` — HTTP API; `static/` — сайт.
