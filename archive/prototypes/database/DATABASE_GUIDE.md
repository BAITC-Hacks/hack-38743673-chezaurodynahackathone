# База профилей SQLite

Готовая база: `data/profiles.sqlite3`. В ней 96 профилей:

| Происхождение | Количество | Метки |
| --- | ---: | --- |
| Исходные записи из `contractors.csv` | 53 | `synthetic=0`, `source_type=csv` |
| Синтетические записи, уже находившиеся в CSV | 13 | `synthetic=1`, `source_type=csv` |
| Дополнительно сгенерированные тестовые профили | 30 | `synthetic=1`, `source_type=generated` |

Метка «исходный» означает происхождение из предоставленного каталога, а не независимую
проверку реальности подрядчика. Исходные имена анонимизированы в CSV. Неизвестные
`max_hours` и `experience_years` сохраняются как `NULL`.

Указанный `profile-generator-set.txt` оказался пустым (0 байт). Поэтому добавленные
30 записей созданы по отдельным явным правилам `synthetic_profile_rules.json`.
Описания и имена обозначают их как синтетические; реальные отзывы, награды и контакты
не выдумывались. Генератор работает локально, без ИИ и API-ключа.

## Создание и повторный импорт

В PowerShell из папки `Hackathon`:

```powershell
python init_database.py
```

Команда импортирует CSV и генерирует 30 профилей. Повторный запуск пропускает
совпадающие записи: дубликаты не создаются. Если существующий ID содержит другие
данные, вся новая партия откатывается с сообщением о конфликте. Существующие
профили не удаляются и не перезаписываются.

Другая база и только содержимое CSV:

```powershell
python init_database.py --db data/catalog_only.sqlite3 --generate 0
```

Другая база со 100 новыми синтетическими профилями:

```powershell
python init_database.py --db data/catalog_166.sqlite3 --generate 100
```

`--generate` задаёт число профилей, которые генератор подготовит к импорту; команда
не уменьшает уже существующую базу. Первые 30 записей при `--generate 100` совпадают
с результатом `--generate 30`, если файл правил не изменён.

Пути можно задать через `--csv`, `--db`, `--rules`. `--rules` принимает JSON по схеме
примерного файла. Передача пустого `profile-generator-set.txt` завершится понятной
ошибкой. Для нового независимого набора измените `seed` в копии JSON-правил.
ID имеют вид `SYN-v1-20260923-0001`; версия алгоритма и seed входят в ID.

## Схема и календарь

| Объект | Данные |
| --- | --- |
| `profiles` | Имя, город, цена, описание, длительность, опыт, метки происхождения, границы календаря |
| `profile_categories` | Категории каждого профиля |
| `profile_event_formats` | Поддерживаемые форматы мероприятий |
| `profile_languages` | Языки |
| `profile_busy_dates` | Занятые даты |
| `profiles_for_ranking` | SQL-представление всех полей; списки объединены через `\|` |

Связанные таблицы используют внешние ключи и составные первичные ключи. Индексы
созданы для города, цены, категорий, форматов, языков и занятых дат.
Схема находится в `schema.sql`, версия БД — `PRAGMA user_version = 1`.
`open_database()` включает проверку внешних ключей для каждого соединения.

Календарь предоставленного CSV и стандартного генератора покрывает период
2026-09-23 — 2026-12-31. Его границы сохранены у каждого профиля.
Пустой список `busy_dates` означает отсутствие занятых дат **в пределах покрытия**.
Вне покрытия отсутствие занятой даты не подтверждает доступность. Для импорта
другого CSV доступны `--calendar-start` и `--calendar-end`.

## Чтение для сайта

```python
from profile_database import open_database, fetch_profiles
from smartmatch import rank_profiles
from profile_explanations import explain_profiles

def recommend(order, eligible_ids):
    # eligible_ids получает другой модуль после жёсткой фильтрации.
    with open_database() as connection:
        candidates = fetch_profiles(connection, eligible_ids)
    selected = rank_profiles(order, candidates)
    return explain_profiles(order, selected)
```

`fetch_profiles` возвращает обычные словари: коллекции — списками, флаги — `bool`.
Порядок `eligible_ids` сохраняется. Неизвестные ID вызывают ошибку, чтобы случайно
не потерять кандидатов. Без `eligible_ids` метод читает весь каталог для управления
данными. Он не проверяет соответствие условиям заказа.

Если внешний модуль работает непосредственно через SQL, можно читать
`profiles_for_ranking`. Значения `categories`, `event_formats`, `languages` и
`busy_dates` там разделены символом `|`. Текущие модули ранжирования и объяснений
совместимы с этим форматом. Связанные таблицы доступны разработчику первого этапа;
бизнес-правила жёсткого отбора здесь не реализуются.

## Проверка и передача

```powershell
python -m unittest discover -v
```

Для передачи БД нужны `profile_database.py`, `init_database.py`, `generate_profiles.py`,
`schema.sql`, `synthetic_profile_rules.json`, `contractors.csv`, `test_profile_database.py`
и этот файл инструкции. Можно передать также готовый демонстрационный снимок
`data/profiles.sqlite3`; без него команда `python init_database.py` создаст каталог заново.
Установка сервера СУБД и сторонних Python-пакетов не требуется.
