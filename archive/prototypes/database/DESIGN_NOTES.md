# SmartMatch: база, ранжирование и объяснение профилей

Два модуля для Python 3.11+: `smartmatch.py` выбирает до трёх кандидатов после
внешней жёсткой фильтрации; `profile_explanations.py` сравнивает выбранные карточки
и добавляет к каждой краткое объяснение. [Настройка ключа и прокси — API_SETUP.md](API_SETUP.md).

Каталог хранится в `data/profiles.sqlite3`: 53 исходных профиля, 13 синтетических
из CSV и 30 дополнительно сгенерированных. Создание или повторный импорт:
`python init_database.py`. Схема, чтение из Python и правила генерации описаны
в [DATABASE_GUIDE.md](DATABASE_GUIDE.md). Жёсткий отбор выполняется внешним модулем.

## Этап 2: ранжирование

`smartmatch.py` принимает кандидатов, которые уже прошли жёсткую фильтрацию в другом компоненте веб-сервиса. Модуль не читает CSV, не подключается к БД и не проверяет дату, город или категорию. Вход `filtered_rows` — последовательность словарей или строк `sqlite3.Row`, полученных из БД.

Описания сравниваются с предпочтениями заказчика через OpenAI API. Модель не обучается при запуске приложения. По умолчанию задан endpoint `https://api.openai.com/v1/chat/completions` и модель `gpt-5.4-nano`, предназначенная для быстрых задач классификации и ранжирования. Достаточно указать только ключ в окружении веб-сервера:

```text
AI_PROXY_API_KEY=ваш-ключ-OpenAI
```

При необходимости другого совместимого прокси или модели можно переопределить `AI_PROXY_URL` и `AI_PROXY_MODEL`. Не записывайте ключ в `smartmatch.py`, README, JavaScript или GitHub-репозиторий.

## Локальная проверка ключа

1. Скопируйте `set_test_key.ps1.example` в `set_test_key.ps1`.
2. Откройте `set_test_key.ps1` и вставьте свой новый ключ вместо текста-заглушки.
3. В PowerShell из папки проекта выполните:

```powershell
. .\set_test_key.ps1
python verify_openai_proxy.py
```

`set_test_key.ps1` исключён из Git. Ключ действует только в текущем окне PowerShell. `verify_openai_proxy.py` отправляет один реальный запрос к OpenAI и выводит ранжированный результат; он может расходовать средства API-проекта.

Прокси должен вернуть в `choices[0].message.content` JSON с оценкой `relevance` от 0 до 1 для каждого индекса входного профиля:

```json
{"scores":[{"index":0,"relevance":0.8},{"index":1,"relevance":0.3}]}
```

Вызов из обработчика сайта:

```python
from smartmatch import rank_profiles

# filtered_rows — результат жёсткой фильтрации, полученный другим модулем из БД.
top_three = rank_profiles(order, filtered_rows)
```

При тестировании можно передать свой объект `model` с методом `relevance(preferences, descriptions)`. В модель уходят только предпочтения и описания; имена, `id`, категории и даты не используются для расчёта. Результат сохраняет исходную строку БД в поле `profile`.

Каждый кандидат начинает со 100 баллов. Несоответствия вычитают баллы: текст до 34, цена относительно бюджета до 30, язык до 12, длительность до 10, качество исходных данных до 14. Профили не исключаются на этом этапе. Возвращаются три записи с наибольшим остатком; при равном балле сохраняется порядок строк, переданных из БД. Если свободные предпочтения не указаны, текстовый штраф равен нулю и прокси не вызывается.


## Этап 3: сравнение и объяснения

`profile_explanations.py` получает результат `rank_profiles` и одним запросом
сравнивает все выбранные профили между собой и с пожеланиями заказчика. Модель
по умолчанию — `gpt-5.4-mini`. Для каждого профиля возвращаются 2–3 кратких предложения.
Этот этап сохраняет число карточек, их порядок, баллы и исходные данные; ничего не
сортирует и не исключает. При выдаче из одного или двух кандидатов описывает всех
имеющихся; пустой список возвращается без API-вызова. Более трёх карточек — ошибка входа.

В анализ входят описание, цена, форматы, языки, максимальная длительность,
стаж (`experience_years`), специализация (`specialties`), услуги (`services`),
оборудование (`equipment`), рейтинг (`rating`), количество отзывов (`review_count`),
признаки синтетических данных и восстановленной цены. Дополнительные поля
необязательны: отсутствующие факты модель должна обозначать как неизвестные.
Списки характеристик должны содержать простые значения, а не вложенные объекты.

Город, даты, ID/номер, телефон и ФИО не включаются в запрос. Из свободного текста
скрываются известные значения этих полей и распространённые форматы дат, телефонов
и email. Это не универсальное распознавание личных данных: неизвестные имена и
города внутри описания лучше очистить на стороне подготовки каталога.
Числа цены, длительности и стажа сохраняются для сравнения.

Пример соединения этапов в серверном обработчике:

```python
from smartmatch import rank_profiles
from profile_explanations import ExplanationError, explain_profiles

def build_recommendations(order, filtered_rows):
    selected = rank_profiles(order, filtered_rows)
    try:
        profiles = explain_profiles(order, selected)
    except ExplanationError:
        # При сбое третьего этапа сайт сохраняет все выбранные карточки.
        return {"profiles": selected, "explanations_status": "unavailable"}
    return {"profiles": profiles, "explanations_status": "ready"}
```

Каждый элемент результата содержит исходные поля `profile`, `score`, `penalties`,
`text_relevance`, а также `explanation` (готовый текст) и `explanation_sentences`
(массив из 2–3 предложений). Выводите текст на сайте как текст, без вставки в `innerHTML`.
Пропуски, дубликаты, чужие индексы, обрыв ответа и неверное число предложений приводят
к `ExplanationError`; неполные объяснения не выдаются за успешный результат.

Автономная демонстрация: `python verify_profile_explanations.py`.
Один реальный вызов после настройки ключа: `python verify_profile_explanations.py --live`.
Пример входа находится в `examples/selected_profiles.json` и содержит только вымышленные данные.
Модульные тесты проверяют контракт и сохранение карточек. Качество сравнения и
достоверность текста генеративной модели нужно оценивать на реальных запросах;
проверка формата ответа сама по себе не доказывает достоверность всех утверждений.

## Файлы для передачи команде

Передайте `smartmatch.py`, `profile_explanations.py`, файлы `test_*.py`,
`verify_openai_proxy.py`, `verify_profile_explanations.py`, папку `examples`,
`README.md`, `API_SETUP.md`, `set_test_key.ps1.example` и `.gitignore`.
Локальный `set_test_key.ps1` с ключом, `.env` и `__pycache__` в передачу не включаются.
Для базы также нужны `profile_database.py`, `init_database.py`, `generate_profiles.py`,
`schema.sql`, `synthetic_profile_rules.json`, `contractors.csv`, `DATABASE_GUIDE.md`.
Готовую `data/profiles.sqlite3` можно передать вместе с ними или создать командой импорта.
