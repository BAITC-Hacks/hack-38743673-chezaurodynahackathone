# Этап 2: ранжирование профилей

`smartmatch.py` принимает кандидатов, которые уже прошли жёсткую фильтрацию в другом компоненте веб-сервиса. Модуль не читает CSV, не подключается к БД и не проверяет дату, город или категорию. Вход `filtered_rows` — последовательность словарей или строк `sqlite3.Row`, полученных из БД.

Описания сравниваются с предпочтениями заказчика через OpenAI API. Модель не обучается при запуске приложения. По умолчанию задан endpoint `https://api.openai.com/v1/chat/completions` и модель `gpt-5.4-nano`, предназначенная для быстрых задач классификации и ранжирования. Достаточно указать только ключ в окружении веб-сервера:

```text
AI_PROXY_API_KEY=ваш-ключ-OpenAI
```

При необходимости другого совместимого прокси или модели можно переопределить `AI_PROXY_URL` и `AI_PROXY_MODEL`. Не записывайте ключ в `smartmatch.py`, README, JavaScript или GitHub-репозиторий.

## Локальная проверка ключа

1. Скопируйте `set_test_key.ps1.example` в `set_test_key.ps1`.
2. Откройте `set_test_key.ps1` и вставьте свой новый ключ вместо текста-заглушки.
3. В PowerShell из папки проекта выполните:

```powershell
. .\set_test_key.ps1
python verify_openai_proxy.py
```

`set_test_key.ps1` исключён из Git. Ключ действует только в текущем окне PowerShell. `verify_openai_proxy.py` отправляет один реальный запрос к OpenAI и выводит ранжированный результат; он может расходовать средства API-проекта.

Прокси должен вернуть в `choices[0].message.content` JSON с оценкой `relevance` от 0 до 1 для каждого индекса входного профиля:

```json
{"scores":[{"index":0,"relevance":0.8},{"index":1,"relevance":0.3}]}
```

Вызов из обработчика сайта:

```python
from smartmatch import rank_profiles

# filtered_rows — результат жёсткой фильтрации, полученный другим модулем из БД.
top_three = rank_profiles(order, filtered_rows)
```

При тестировании можно передать свой объект `model` с методом `relevance(preferences, descriptions)`. В модель уходят только предпочтения и описания; имена, `id`, категории и даты не используются для расчёта. Результат сохраняет исходную строку БД в поле `profile`.

Каждый кандидат начинает со 100 баллов. Несоответствия вычитают баллы: текст до 34, цена относительно бюджета до 30, язык до 12, длительность до 10, качество исходных данных до 14. Профили не исключаются на этом этапе. Возвращаются три записи с наибольшим остатком; при равном балле сохраняется порядок строк, переданных из БД. Если свободные предпочтения не указаны, текстовый штраф равен нулю и прокси не вызывается.

## Проверка

```powershell
python -m unittest -v test_smartmatch.py
```

Модульные тесты используют заглушку модели и не обращаются к API.
