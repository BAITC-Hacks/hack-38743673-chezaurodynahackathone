# Анализ кода SmartMatch MVP

Проверена структура рабочего приложения, HTTP-контракты, фронтенд, импорт CSV, ранжирование, адаптеры ИИ, новая SQLite-интеграция, скрипты, тесты, конфигурация контейнера и ранние прототипы команды. Единственная актуальная инструкция запуска — [README.md](../README.md). Этот документ фиксирует устройство и границы реализации; он не является отдельным вариантом настройки.

## Что объединено

| Часть | Состояние до объединения | Решение в MVP |
|---|---|---|
| Сайт и сервер | Рабочая форма использовала CSV и каталог в памяти; часть новых параметров не проходила через весь запрос | Единый запрос от формы до `SearchQuery`, `HardFilter`, ранжирования и сохранения |
| Подбор | Первый рабочий пакет и независимый второй этап имели разные формулы и конфигурации | Канонический алгоритм в `smartmatch/engine.py`; общий фильтр до любых оценок |
| Объяснения | Третий прототип делал дополнительный генеративный запрос и ожидал формат второго | Сервер строит объяснение из проверенной цитаты и фактов профиля; дополнительных придуманных характеристик нет |
| Хранилище | Прототип базы не подключался к HTTP; документы ссылались на отсутствующий `profile_database.py` | Рабочие `database.py` и `schema.sql`, импорт, история и отметки через `MatchingService` |
| Конфигурация | `AI_PROXY_*`, `EXPLANATION_PROXY_*` и настройки рабочего приложения конкурировали | Один корневой `.env`; основное подключение — `OPENAI_API_KEY` и `SMARTMATCH_AI_*` |
| Каталог | В старой документации смешивались 66 входных и 30 дополнительно сгенерированных записей | По умолчанию только исходные 66; генерация отдельной явной командой |
| Документация | Несколько README с разными путями и командами | Один общий README; исторические записи помечены и перенесены в архив |

## Рабочие модули

### Вход и интерфейс

`run.py` вызывает `smartmatch.web.main`. Параметры запуска определяют адрес, порт, исходный CSV и постоянную БД. Windows-лаунчер использует ту же точку входа. Открытие браузера выполняется после успешного создания сервера.

`smartmatch/static/index.html`, `styles.css` и `app.js` образуют интерфейс без сборки. Форма загружает списки значений и календарь через `/api/meta`. Описание превращается в редактируемые параметры; изменения, сделанные вручную, сохраняются. Изменение условий помечает предыдущую выдачу как устаревшую. Данные профилей экранируются при выводе. Встроенная CSS-копия обновляется `scripts/embed_styles.py`, исходником остаётся `styles.css`.

`web.py` обслуживает статические файлы только из `static/`. JSON-запросы ограничены по размеру; проверяются тип содержимого, структура, типы полей и источник браузерного POST-запроса. `/api/health` проверяет доступность базы. Ошибка SQLite возвращает 503. Секреты и история не имеют маршрутов скачивания. Проверка Origin — вспомогательная мера, она не является авторизацией.

### Общая цепочка приложения

`service.py` — место соединения компонентов. При старте он инициализирует SQLite и строит движок по каталогу из БД. При подборе создаёт проверенный `SearchQuery`, вызывает общую цепочку ранжирования и записывает нормализованный запрос с полученным ответом. Только после успешной записи клиент получает `search_id` и `saved: true`.

`models.py` определяет неизменяемые объекты профиля и запроса. Бюджет и нижняя цена — целые суммы в тенге; нижняя граница не выше верхней. Длительность конечна и находится в интервале (0, 24]. `include_synthetic` — логическое значение, сортировка ограничена тремя именованными режимами.

### Каталог и постоянная база

`repository.py` проверяет CSV: обязательные сведения, уникальность ID, положительную цену, признаки происхождения, конечность длительности и календарь. Некорректные строки изолируются с причиной. Явно пустое поле занятых дат означает отсутствие отмеченной занятости в фиксированном периоде; отсутствующий столбец не трактуется как подтверждение доступности. Границы календаря заданы явно, а не вычисляются по самой ранней и поздней занятой дате.

`database.py` использует короткие SQLite-соединения, внешние ключи, WAL и транзакции. Первичный импорт выполняется один раз, его состояние и изолированные строки сохраняются. Последующие старты не перезаписывают каталог. Нормализованные связи категорий, языков, форматов и занятости хранятся отдельно от профиля; порядок исходных значений сохраняется.

Каждый подбор, включая пустой результат, сохраняет UUID, время UTC, запрос и полный снимок ответа. Таблица выдачи связывает поиск с реально показанными ID и их местом. Отметка допустима только для такой пары; повторная отметка не создаёт дубль. Отмечать можно несколько карточек; это история интереса, не факт заказа или оплаты.

`scripts/init_database.py` позволяет создать каталог и явно добавить синтетические записи. Рабочий генератор перенесён в `smartmatch/generate_profiles.py`; он воспроизводим по локальным правилам, сохраняет происхождение и не использует ИИ. По умолчанию генерация выключена. `scripts/export_history.py` выдаёт локальную JSON-выгрузку и не перезаписывает уже существующий файл.

### Фильтры, оценка и объяснения

`hard_filter.py` содержит одну реализацию проверки происхождения, даты, обеих границ цены, формата, языка и длительности. Город и категория выбирают рынок до этих проверок. Одни и те же правила используются для результата, счётчиков этапов и причин отказа. Кандидат может иметь несколько причин.

`engine.py` проверяет календарь, различает отсутствие рынка и отсутствие допустимых кандидатов, оценивает оставшихся и сортирует весь допустимый набор. Только после этого берутся три карточки. При равенстве ключа сортировки ID обеспечивает стабильность. Сортировка по цене не превращается в сортировку уже отобранной тройки.

Компоненты балла: текст 34%, бюджет 30%, язык 12%, длительность 10%, качество исходных данных 14%. Бюджетный максимум около 72% заданного потолка — эвристика проекта. Снижение за синтетические или восстановленные данные — эвристика происхождения, а не оценка реальной надёжности человека.

`text.py` строит локальный TF-IDF-подобный индекс: частотные веса, косинусное сходство и упрощённое удаление русских окончаний. Это поиск по словам, не обученная семантическая модель. Из профиля выбирается предложение, связанное с найденными словами; при длинном тексте оно сокращается.

### Разбор текста и ИИ

`brief.py` локально распознаёт категории, города, форматы, язык, полную дату, бюджет и часы. Неоднозначности оставляются для пользователя. Не подставляется текущий год, не выполняется конвертация валюты. ИИ-разбор требует цитату для каждого извлечённого значения; числовые значения и даты дополнительно сверяются с её содержимым.

`ai.py` читает только корневую конфигурацию и окружение, не отдаёт ключ браузеру и ограничивает провайдерские ответы. OpenAI использует Responses API и строгую схему. Также сохранены адаптеры Gemini и совместимого Chat Completions. Ошибки провайдера преобразуются в безопасное общее сообщение; тело внешней ошибки не публикуется клиенту. Перенаправления не разрешаются, чтобы не переслать ключ на другой адрес.

Перед оценкой модель получает только профили, прошедшие общий фильтр. В ответе обязательны все допустимые ID ровно один раз, конечные оценки 0–100 и цитаты из соответствующих описаний. Ошибка хотя бы одной записи отклоняет весь модельный результат; локальный подбор сохраняет те же обязательные условия. Проверенная цитата не доказывает релевантность субъективной оценки, поэтому балл остаётся рекомендацией, а не гарантией.

Кэш модели ограничен 128 успешными ответами в памяти. Идентичные параллельные запросы синхронизированы; одновременно разрешены два сетевых вызова. Результаты могут измениться после очистки кэша или перезапуска. Локальный режим воспроизводим без внешнего сервиса.

## Исторические прототипы

`archive/prototypes/ranking` содержит отдельный контракт `rank_profiles`: мягкие штрафы от 100 баллов, идентификаторы входных строк и самостоятельные переменные `AI_PROXY_*`. Он не проверяет город, дату и категорию и не подключается к рабочей БД. Его формула и порядок при равенстве отличаются от текущего `engine.py`; импорт такого модуля напрямую изменил бы поведение сайта.

`archive/prototypes/explanations` содержит отдельный генератор 2–3 предложений после ранжирования. Он скрывает известные поля и некоторые форматы личных данных, но не гарантирует универсального обезличивания. Проверяет структуру ответа и сохранение числа карточек, однако произвольные сгенерированные утверждения не сверяет с каталогом. Поэтому рабочий MVP использует проверенные цитаты и серверную сборку объяснений.

`archive/prototypes/database` сохраняет раннюю схему, генератор и тесты для ожидавшегося модуля `profile_database.py`. В полученном наборе этот модуль отсутствовал; инструкции ссылались также на другие пути. Архив сохранён для истории, а нужные функции импортирования и генерации реализованы в основном пакете с единым контрактом.

Старые тесты в архиве не входят в проверку запускаемого MVP. Актуальный набор — `tests/`, команда указана в README. В архиве нет гарантии автономного запуска, и его инструкции не следует смешивать с текущей конфигурацией.

## Проверки и пределы вывода

Модульные и интеграционные тесты проверяют обязательные фильтры, сортировку до top-3, случаи без результатов, разбор, валидацию модели, локальный fallback, HTTP-контракты и сохранение в SQLite. Сетевой транспорт подменяется тестовым: прохождение этих тестов не подтверждает доступность живого API или качество ответов конкретной модели.

`scripts/evaluate.py` выполняет демонстрационные запросы и 100 повторов локального подбора. Результаты и времена печатаются JSON, а не фиксируются в документации как постоянные характеристики. В CI запускается рабочий набор тестов; статус конкретного запуска CI нужно смотреть отдельно от локальных проверок.

## Что остаётся за границей MVP

- Для публикации необходимы HTTPS, контроль доступа, квоты и защита расходов API; стандартный HTTP-сервер и проверка Origin этого не обеспечивают.
- SQLite не шифруется приложением; доступ к файлу и резервным копиям контролирует оператор. История не имеет автоматического срока хранения или удаления.
- В БД не записываются IP и отпечатки браузера, но консольный HTTP-журнал содержит адрес клиента. Текст пожеланий может содержать личные сведения и сохраняется без автоматического редактирования.
- Каталог загружается при старте. Изменение CSV не выполняет миграцию существующей БД, изменение файла БД не обновляет индекс уже работающего сервера.
- Нет онлайнового календаря, подтверждения цены, контактов и заказа. Кнопка отметки — только сбор интереса.
- Нет оценки качества по размеченным пользовательским данным. История уже собирается, но не является обратной связью об успешном мероприятии и не запускает обучение модели.
- Поддерживается один язык в условии, а не логическое требование нескольких языков одновременно. Веб-форма ограничивает описание 5000 символами и длительность шагом 0,5 часа; API допускает 6000 символов и любую конечную длительность (0, 24].
- Реальный вызов OpenAI и запуск Docker в текущей проверке не выполнялись. Модульные тесты проверяют их программные контракты, а не доступность учётных данных или окружения развёртывания.

Эти ограничения явно отражены в README и интерфейсе там, где влияют на действия пользователя.
